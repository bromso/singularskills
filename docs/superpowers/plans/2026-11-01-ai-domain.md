# AI Domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an `ai` domain (12 skills, an 8-phase gated workflow, two references, docs, one eval) to the singularskills pack.

**Architecture:** Same shape as project 5's `analytics` domain: Markdown skills under `skills/ai-*/SKILL.md`, a workflow file that drives generated gates, conductor tables and adapters, two domain-list entries in the validator and pack-tools, and docs pages in the `analytics` section's formats.

**Tech Stack:** Bun 1.3, Turborepo, TypeScript, Vitest, Biome (tabs, width 100), Fumadocs.

**Spec:** `docs/superpowers/specs/2026-11-01-ai-domain-design.md`

## Global Constraints

- Domain `ai`. Phase skills: `ai-define`, `ai-approach`, `ai-prompt-design`, `ai-experience`, `ai-build`, `ai-evaluate`, `ai-ship`, `ai-monitor` (phases 1–8). Utilities: `ai-prompt-review`, `ai-red-team`, `ai-judge-check`, `ai-model-compare`.
- Artifacts: `01-define.md`, `02-approach.md`, `03-prompt.md`, `04-experience.md`, `05-build.md`, `06-evaluate.md`, `07-ship.md`, `08-monitor.md` under `.singularskills/ai/<project>/`. Requires are exactly as spec §4's table.
- Utility artifacts: `red-team/<date>-<slug>.md` and `judges/<date>-<slug>.md` (`phase: null`, `gate: none`). `ai-prompt-review` and `ai-model-compare` write no file.
- Workflow title and README methodology: "AI Feature Lifecycle". Docs and README name: "AI Product".
- Totals become **315 skills**, **19 domains**, **20** eval cases, **22** workflows.
- No evaluation-tool files, no network calls, and no skill calls a model API. `ai-build` writes the spec only and tells the user to run `/development-plan <project>` with the same project name, then `/development-build`.
- `ai-evaluate`:
  - Claude does the first pass, then stops for a person to confirm the groups.
  - Unconfirmed groups are marked **proposed**, and no check is built from a proposed group.
  - It never invents human labels.
  - It reads `.singularskills/development/<project>/` when it exists.
- Re-runs of Evaluate or Monitor first keep the previous file as `06-evaluate-<date>.md` or `08-monitor-<date>.md`.
- Labels: `computed`, `not measured`, `target`. Scripts write aggregates. The row-level artifacts (evaluate notes, judge disagreements, red-team inputs) may list a row or output ID with a short quote, with personal data always replaced by placeholders.
- `CROSS_DOMAIN_READS.ai = ["research", "support", "analytics", "development", "compliance"]`. `ai` is in both compute sets and in no disclaimer group. No other domain's skills are edited.
- Utilities take a project the user names whether or not its folder exists (the rule wording from `skills/analytics-investigate/SKILL.md`).
- Generated files only via the generators.
- Descriptions:
  - start with a verb the validator recognises: check `packages/skill-validator/src/rules.ts`, since "Name", "Specify" and "Explain" are not in the list;
  - include `Use when …` with at least 6 words;
  - are 120–400 characters;
  - include a `Not for …; see /…` line against spec §3's neighbours.
- Any docs `description` containing `: ` is quoted.
- Commits end `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Pack-tools commands need `bun run build` in `packages/pack-tools` first.
- Until Task 6, verify with `bun run check` in `packages/pack-tools` plus `bun run lint:skills`. A skill may not name an `/ai-*` skill that a later task creates.

## Review Focus

1. **No confirmation in Evaluate** ("I won't be around"): the groups are written as proposed, and the artifact contains no checks built from them. Pinned by Task 3's grep for "proposed" and acceptance run 2.
2. **Judge check with too few human labels** (say 5 rows): it says the sample is too small to trust either way rather than approving the judge. Pinned by Task 4's grep for "too few" and acceptance run 5's second case.
3. **Prompt injection through retrieved documents**, not only from the user's message: the prompt-design and red-team skills both name it. Pinned by Task 3's and Task 4's greps for "retrieved" and acceptance run 4.
4. **Personal data inside sample outputs** (emails, account numbers): no file under `.singularskills/ai/` holds them, scripts included. Pinned by acceptance run 2's grep over every file.
5. **Re-running Evaluate** over an existing `06-evaluate.md`: the previous file is kept under its date. Pinned by Task 3's grep for "06-evaluate-<date>.md" and acceptance run 2's re-run.
